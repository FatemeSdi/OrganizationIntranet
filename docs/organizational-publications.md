# اطلاع‌رسانی سازمانی

## وضعیت اعمال نهایی — ۲۰۲۶/۰۹/۱۶

پس از درخواست صریح کاربر برای اعمال تغییرات، اسکریپت up با اتصال تنظیم‌شده API روی دیتابیس فعلی اجرا شد. بررسی مستقیم SQL وجود جدول، ۱۱ ستون، دو کلید خارجی و چهار Index ثانویه را تأیید کرد؛ جدول فعلاً بدون محتوا است. Build نسخه Release مجدداً موفق شد. فرمان توقف و راه‌اندازی مجدد API/Portal/Admin توسط بررسی خودکار مجوز با پیام `blocked by policy` رد شد؛ در نتیجه به‌روزرسانی فرایندهای در حال اجرا تأیید نشده و راه‌اندازی مجدد از Visual Studio باقی است. توضیحات عدم اجرای SQL در گزارش اولیه پایین، مربوط به مرحله پیش از این درخواست هستند.

قابلیت در معماری پنج‌پروژه‌ای فعال پیاده شده است. خبر (`News`)، اطلاعیه (`Announcement`) و بخشنامه (`Circular`) دارای عنوان، خلاصه و متن ساده هستند. مدیر می‌تواند محتوا را ایجاد یا ویرایش کند، به شکل پیش‌نویس ذخیره کند، منتشر کند یا با برداشتن گزینه انتشار به پیش‌نویس برگرداند. تاریخ ایجاد، آخرین ویرایش و انتشار و شناسه ایجادکننده/ویرایش‌کننده در سرور ثبت می‌شوند. ذخیره موفق در لاگ API نیز ثبت می‌شود.

## مسیرها و لایه‌ها

- Domain: موجودیت `Publication` مستقل از اعلان‌های سامانه‌های بیرونی.
- Application: سرویس `PublicationService` و قرارداد `IPublicationRepository`؛ اعتبارسنجی، زمان‌ها و چرخه انتشار.
- API/Data: نگاشت EF و Repository با فیلتر انتشار در دیتابیس، مرتب‌سازی پایدار و صفحه‌بندی ۲۰تایی.
- قراردادهای انتقال: `shared/Contracts/PublicationContracts.cs`؛ UIها همچنان فقط از HTTP استفاده می‌کنند.
- Admin: `/Admin/Publications` و `/Admin/Publications/Edit?id=...`؛ لینک در منوی مدیریت. بدون id محتوای جدید ایجاد می‌شود.
- Portal: `/Publications` و `/Publications/Details/{id}`؛ بخش اخبار صفحه اصلی نیز چهار مطلب آخر و تعداد واقعی مطالب منتشرشده را نمایش می‌دهد.
- API خواندن: `GET /api/publications` و `GET /api/publications/{id}`؛ نیازمند ورود. پیش‌نویس حتی با دانستن شناسه ۴۰۴ می‌دهد.
- API مدیریت: `GET/POST /api/admin/publications` و `GET/POST /api/admin/publications/{id}`؛ نیازمند نقش ADMIN. POST مجموعه برای ایجاد و POST شناسه برای ویرایش است.
- فیلتر فهرست: `kind`، `search` (عنوان و خلاصه) و `page` از ۱. پاسخ شامل Items، Total، Page و PageSize است؛ متن کامل فقط در جزئیات ارسال می‌شود.

تمام مطالب منتشرشده برای کاربران واردشده سازمان قابل مشاهده‌اند. کنترل نقش در API و UI، کلید کلاینت، Bearer Token، Antiforgery و HTML encoding حفظ شده‌اند. متن HTML اجرا نمی‌شود. این قابلیت شامل پیوست، ارسال ایمیل/پیامک یا اعلان شخصی نیست.

## نصب دیتابیس و بازگشت

پیش از استقرار نسخه جدید، اسکریپت `tools/sql/001-publications-up.sql` را روی دیتابیس موجود API اجرا کنید؛ جدول `Notify.Publication` و FKها/Indexهای مربوط ایجاد می‌شوند. اسکریپت برای اجرای مجدد پس از نصب کامل مناسب است؛ جدول‌های قبلی را تغییر نمی‌دهد. اجرای خودکار هنگام شروع برنامه وجود ندارد. بدون این جدول، مسیرهای جدید و صفحه اصلی پورتال به خطای سرویس برخورد می‌کنند.

برای بازگشت، ابتدا نسخه قبلی برنامه را مستقر کنید و سپس از `tools/sql/001-publications-down.sql` استفاده کنید. اسکریپت در صورت وجود محتوا عمداً از حذف جدول خودداری می‌کند تا ابتدا خروجی داده تهیه و حذف آن جداگانه تصمیم‌گیری شود. اسکریپت‌های SQL در این تغییر روی دیتابیس عملیاتی اجرا نشده‌اند.

## تأیید

`dotnet build OrganizationIntranet.sln -c Release --no-restore`

`dotnet test tests/OrganizationIntranet.SmokeTests/OrganizationIntranet.SmokeTests.csproj -c Release --no-restore`

Build و اجرای نهایی ۱۸ آزمون موفق بودند. آزمون‌های جدید چرخه پیش‌نویس/انتشار/لغو انتشار، انواع محتوا، دسترسی، اعتبارسنجی، جست‌وجو، عدم اجرای HTML و فرم دارای Antiforgery را با API و Razor واقعی و SQLite موقت بررسی می‌کنند. SQL Server عملیاتی و ظاهر صفحات در مرورگر تأیید نشده‌اند. خروجی Debug در زمان بررسی توسط API/Visual Studio قفل بود؛ Release مستقل بررسی شد. پنج هشدار آسیب‌پذیری NuGet در وابستگی‌های موجود Azure.Identity، Microsoft.Identity.Client و System.Formats.Asn1 گزارش شد.
