# اطلاع‌رسانی سازمانی

## تکمیل یکپارچگی — ۲۰۲۶/۰۹/۱۷

کنترل ویرایش هم‌زمان در Domain، Application، Repository، API، قراردادها و فرم مدیریت اضافه شد. هر ذخیره شماره `Revision` را افزایش می‌دهد؛ ویرایش با شماره قدیمی یا بدون شماره با HTTP 409 رد می‌شود. EF نیز رقابت بین خواندن و ذخیره را کنترل می‌کند. فرم در حالت تعارض متن واردشده را حفظ می‌کند تا مدیر پیش از بازکردن نسخه جدید آن را کپی کند. کلاینت‌های API باید هنگام ویرایش، Revision دریافتی از جزئیات را ارسال کنند. ایجاد محتوا به Revision نیاز ندارد.

اسکریپت `tools/sql/002-publications-integrity-up.sql` پس از تهیه و تأیید پشتیبان SQL Server روی دیتابیس تنظیم‌شده اجرا شد. بررسی مستقیم، ۱۲ ستون، دو FK، چهار Index ثانویه و دو Check Constraint فعال و معتبر برای نوع محتوا و سازگاری وضعیت انتشار را تأیید کرد. جدول هنگام بررسی بدون محتوا بود. این تغییر هیچ مطلب نمونه‌ای منتشر نمی‌کند.

نصب جدید به ترتیب اسکریپت‌های 001 و 002 است. اسکریپت 002 قابل اجرای مجدد است؛ فایل down متن مطالب را حفظ می‌کند و تنها کنترل‌های افزوده و شماره نسخه را حذف می‌کند. ابتدا برنامه قبلی را مستقر کنید و سپس rollback دیتابیس را اجرا کنید. API و Admin جدید باید با هم راه‌اندازی شوند؛ اجرای نسخه قدیمی API حفاظت Revision را ندارد.

Build پنج پروژه در Release بدون خطا و هشدار موفق شد. شش آزمون مرتبط با اطلاع‌رسانی و دیتابیس موفق شدند. اجرای کامل اولیه ۱۸ موفق و یک شکست در آزمون حساب کاربری داشت: رمز کوتاه `initial` با اعتبارسنجی جدید موجود در بخش احراز هویت سازگار نیست. تغییرات مستقل احراز هویت در این کار دست‌کاری نشدند. تأیید بصری مرورگر و راه‌اندازی مجدد میزبان‌های واقعی انجام نشده است.

گزارش زیر مربوط به پیاده‌سازی اولیه است؛ نتیجه جاری دیتابیس و آزمون‌ها در بخش بالا ثبت شده است.

## وضعیت اعمال نهایی — ۲۰۲۶/۰۹/۱۶

پس از درخواست صریح کاربر برای اعمال تغییرات، اسکریپت up با اتصال تنظیم‌شده API روی دیتابیس فعلی اجرا شد. بررسی مستقیم SQL وجود جدول، ۱۱ ستون، دو کلید خارجی و چهار Index ثانویه را تأیید کرد؛ در زمان اجرای verify تعداد رکوردها صفر بود. Build نسخه Release مجدداً موفق شد. فرمان توقف و راه‌اندازی مجدد API/Portal/Admin توسط بررسی خودکار مجوز با پیام `blocked by policy` رد شد؛ در نتیجه به‌روزرسانی فرایندهای در حال اجرا تأیید نشده و راه‌اندازی مجدد از Visual Studio باقی است. در آخرین بررسی فرایندهای محلی، هیچ فرایند OrganizationIntranet فعال مشاهده نشد؛ فعال‌سازی میزبان‌ها همچنان تأیید نشده است.

قابلیت در معماری پنج‌پروژه‌ای فعال پیاده شده است. خبر (`News`)، اطلاعیه (`Announcement`) و بخشنامه (`Circular`) دارای عنوان، خلاصه و متن ساده هستند. مدیر می‌تواند محتوا را ایجاد یا ویرایش کند، به شکل پیش‌نویس ذخیره کند، منتشر کند یا با برداشتن گزینه انتشار به پیش‌نویس برگرداند. تاریخ ایجاد، آخرین ویرایش و انتشار و شناسه ایجادکننده/ویرایش‌کننده در سرور ثبت می‌شوند. ذخیره موفق در لاگ API نیز ثبت می‌شود.

## مسیرها و لایه‌ها

- Domain: موجودیت `Publication` مستقل از اعلان‌های سامانه‌های بیرونی.
- Application: سرویس `PublicationService` و قرارداد `IPublicationRepository`؛ اعتبارسنجی، زمان‌ها و چرخه انتشار.
- API/Data: نگاشت EF و Repository با فیلتر انتشار در دیتابیس، مرتب‌سازی پایدار و صفحه‌بندی ۲۰تایی.
- قراردادهای انتقال: `shared/Contracts/PublicationContracts.cs`؛ UIها همچنان فقط از HTTP استفاده می‌کنند.
- Admin: `/Admin/Publications` و `/Admin/Publications/Edit?id=...`؛ لینک در منوی مدیریت. بدون id محتوای جدید ایجاد می‌شود.
- Portal: `/Publications` و `/Publications/Details/{id}`؛ بخش اخبار صفحه اصلی نیز چهار مطلب آخر و تعداد واقعی مطالب منتشرشده را نمایش می‌دهد.
- API خواندن: `GET /api/publications` و `GET /api/publications/{id}`؛ نیازمند ورود. پیش‌نویس حتی با دانستن شناسه ۴۰۴ می‌دهد.
- API مدیریت: `GET/POST /api/admin/publications` و `GET/POST /api/admin/publications/{id}`؛ نیازمند نقش ADMIN. POST مجموعه برای ایجاد و POST شناسه برای ویرایش است.
- فیلتر فهرست: `kind`، `search` (عنوان و خلاصه) و `page` از ۱. پاسخ شامل Items، Total، Page و PageSize است؛ متن کامل فقط در جزئیات ارسال می‌شود.

تمام مطالب منتشرشده برای کاربران واردشده سازمان قابل مشاهده‌اند. کنترل نقش در API و UI، کلید کلاینت، Bearer Token، Antiforgery و HTML encoding حفظ شده‌اند. متن HTML اجرا نمی‌شود. این قابلیت شامل پیوست، ارسال ایمیل/پیامک یا اعلان شخصی نیست.

## نصب دیتابیس و بازگشت

برای نصب در محیط دیگری، پیش از استقرار نسخه جدید، اسکریپت `tools/sql/001-publications-up.sql` را روی دیتابیس موجود API اجرا کنید؛ جدول `Notify.Publication` و FKها/Indexهای مربوط ایجاد می‌شوند. اسکریپت برای اجرای مجدد پس از نصب کامل مناسب است؛ جدول‌های قبلی را تغییر نمی‌دهد. اجرای خودکار هنگام شروع برنامه وجود ندارد. بدون این جدول، مسیرهای جدید و صفحه اصلی پورتال به خطای سرویس برخورد می‌کنند.

برای بازگشت، ابتدا نسخه قبلی برنامه را مستقر کنید و سپس از `tools/sql/001-publications-down.sql` استفاده کنید. اسکریپت در صورت وجود محتوا عمداً از حذف جدول خودداری می‌کند تا ابتدا خروجی داده تهیه و حذف آن جداگانه تصمیم‌گیری شود. اسکریپت up روی دیتابیس فعلی اجرا و نتیجه با tools/sql/001-publications-verify.sql بررسی شده است؛ اسکریپت down اجرا نشده است.

## تأیید

`dotnet build OrganizationIntranet.sln -c Release --no-restore`

`dotnet test tests/OrganizationIntranet.SmokeTests/OrganizationIntranet.SmokeTests.csproj -c Release --no-restore`

Build و اجرای نهایی ۱۸ آزمون موفق بودند. آزمون‌های جدید چرخه پیش‌نویس/انتشار/لغو انتشار، انواع محتوا، دسترسی، اعتبارسنجی، جست‌وجو، عدم اجرای HTML و فرم دارای Antiforgery را با API و Razor واقعی و SQLite موقت بررسی می‌کنند. اعمال ساختار SQL Server فعلی با اجرای up و verify تأیید شده است؛ آزمون رفتاری انتشار روی SQL Server عملیاتی و بررسی بصری صفحات در مرورگر انجام نشده‌اند. خروجی Debug در زمان بررسی توسط API/Visual Studio قفل بود؛ Release مستقل بررسی شد. پنج هشدار آسیب‌پذیری NuGet در وابستگی‌های موجود Azure.Identity، Microsoft.Identity.Client و System.Formats.Asn1 گزارش شد.


### شواهد بررسی ثبت‌شده

- اجرای اسکریپت up با ابزار موجود tools/Invoke-DatabaseScript.ps1 و اتصال تنظیم‌شده API با پیام Database script completed پایان یافت.
- خروجی verify: TableExists=1، ColumnCount=11، ForeignKeyCount=2، SecondaryIndexCount=4 و PublicationCount=0 در زمان بررسی.
- گزارش محلی artifacts-publications-tests.log نتیجه ۱۸ آزمون موفق، صفر شکست و صفر آزمون ردشده را ثبت کرد.
- آزمون Publications_enforce_visibility_validation_and_admin_access در tests/OrganizationIntranet.SmokeTests/PortalSmokeTests.cs مشاهده جزئیات پورتال با نشست احرازشده، مخفی‌ماندن پیش‌نویس، لغو انتشار و HTML encoding را بررسی کرد.
- آزمون Publication_editor_requires_antiforgery_and_saves_content ارسال HTTP فرم واقعی Razor مدیریت با Antiforgery، ثبت بخشنامه و بازکردن صفحات ویرایش و فهرست را بررسی کرد.
- این آزمون‌ها با TestServer، API و Razor واقعی و SQLite جدا اجرا شدند؛ آزمون تعاملی مرورگر گرافیکی محسوب نمی‌شوند. در اصلاح این مستند SQL و آزمون‌ها دوباره اجرا نشدند.
