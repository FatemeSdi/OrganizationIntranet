# فاز ۰ — شناخت و تثبیت UI

تاریخ: ۲۰۲۶-۰۹-۱۳

> ادامه بررسی در ۲۰۲۶-۰۹-۱۶: [گزارش تکمیلی آزمون UI](ui-phase-0-verification.md). متن زیر مبنای تاریخی ساختار تک‌پروژه‌ای است؛ برای ساختار فعلی چندپروژه‌ای به CLAUDE.md و گزارش تکمیلی مراجعه شود.

## محدوده و نتیجه

با توجه به نبود چک‌لیست قبلی، محدوده این فاز عبارت است از شناخت ساختار موجود، ثبت قراردادهای UI، بررسی وابستگی‌های مستقیم و اصلاحات محدود پایه. بررسی سورس و اصلاحات زیر انجام شده‌اند؛ تأیید بصری در مرورگر و سناریوهای کاربر واردشده هنوز انجام نشده‌اند. این سند مبنای فاز بعد است، نه تأیید آمادگی انتشار.

مرجع معماری همچنان `CLAUDE.md` است. Razor Pages، PageModelها، EF Core/SQL Server و زیرساخت Authorization موجود حفظ شده‌اند. این فاز تغییری در دیتابیس، ورود، سطح دسترسی یا اتصال سامانه‌ها ایجاد نمی‌کند.

## نقشه UI و مسئولیت‌ها

| بخش | صفحات | Layout و وابستگی‌ها |
|---|---|---|
| ورود و بازیابی رمز | Account/Login، Account/ForgotPassword | `_LayoutAuth`؛ Bootstrap RTL، Vazir محلی، yzen، app-theme، jQuery، Ajax، Toast؛ حالت روشن ثابت |
| پورتال | Portal/Index | `_LayoutApp` سبک؛ CSS و JavaScript داخل صفحه؛ فونت Vazirmatn از Google Fonts؛ منوها و جست‌وجوی مستقل از Bootstrap |
| پروفایل | Account/Profile | `_LayoutApp`؛ Bootstrap RTL، yzen و Toast توسط خود صفحه بارگذاری می‌شوند |
| مدیریت | Admin/Index، Users/Index و Edit، Roles/Index، Applications/Index، Permissions/Index و Assign | `_LayoutAdmin`؛ هدر، سایدبار، منوی حساب، پشتیبانی و Toast مشترک؛ Bootstrap RTL و اسکریپت‌های قالب |
| عمومی | Error و Layout پیش‌فرض | `_Layout` از `_ViewStart`؛ site.css و CSS ایزوله Layout؛ صفحه خطا هنوز متن پیش‌فرض انگلیسی دارد |
| خروج | Account/Logout | رفتار خروج در PageModel؛ بخشی از چرخه احراز هویت |

`Data` محل DbContext، `Models` محل مدل‌های فعلی و `Authorization` محل زیرساخت دسترسی است. لایه Services هنوز ساخته نشده و تعدادی Query در PageModelها هستند. این موضوع بدهی معماری است و نباید با جابه‌جایی نمایشی فایل‌ها در فاز UI تغییر کند.

## قراردادهای تثبیت‌شده

- جهت سند فارسی `rtl` و زبان آن `fa` است. در مدیریت فقط نسخه RTL بوت‌استرپ بارگذاری می‌شود.
- ترتیب استایل‌های قالب: Bootstrap RTL، فونت، styles.css، app-theme.css، آیکن‌ها و سپس استایل اختصاصی صفحه؛ تغییر این ترتیب نیازمند بررسی اثر ظاهری است.
- `_LayoutApp` عمداً حداقل وابستگی را دارد؛ افزودن عمومی Bootstrap به آن می‌تواند با کلاس‌های اختصاصی پورتال تداخل ایجاد کند.
- اسکریپت‌های وابسته پس از کتابخانه مورد نیاز بارگذاری شوند؛ `app-toast.js` به Bootstrap Toast نیاز دارد و متن پیام را با `textContent` درج می‌کند.
- `wwwroot/css/site.css` شامل قواعد سراسری پنهان‌کردن سایدبار است؛ بدون بررسی نباید به Layout مدیریت اضافه شود.
- CSS و JS اختصاصی پورتال فعلاً در همان Razor Page می‌مانند. انتقال آن‌ها به فایل مستقل باید در مرحله‌ای جدا همراه بررسی مسیر assetها و داده‌های Razor انجام شود.
- پنهان‌سازی منو یا فیلتر کارت در مرورگر جایگزین Authorization سرور نیست. تغییر Role-based به Permission-based همچنان تابع ترتیب امن ثبت‌شده در `CLAUDE.md` است.

## اصلاحات انجام‌شده

1. `_Layout` با `lang="fa"` و `dir="rtl"` و Bootstrap RTL هماهنگ شد.
2. فایل Bootstrap LTR اضافی از `_LayoutAdmin` حذف شد؛ نسخه RTL همان کتابخانه کامل است.
3. کنترل تغییر تم و منوی حساب مدیریت برچسب فارسی قابل خواندن برای فناوری‌های کمکی گرفتند.
4. ورودی جست‌وجوی پورتال برچسب قابل دسترس و پیام نبود نتیجه نقش status گرفت.
5. Escape منوی اعلان یا حساب باز پورتال را می‌بندد، `aria-expanded` را اصلاح می‌کند و فوکوس را به کنترل بازکننده بازمی‌گرداند.
6. دکمه بستن Toast فارسی شد و نمونه Bootstrap بعد از پنهان‌شدن dispose می‌شود.

## شواهد بررسی

- `dotnet build --no-restore` قبل و بعد از اصلاحات موفق: صفر خطا، پنج هشدار قبلی. هشدارها مربوط به Azure.Identity 1.10.3، Microsoft.Identity.Client 4.56.0 و System.Formats.Asn1 5.0.0 هستند.
- `node --check wwwroot/assets/js/app-toast.js` موفق.
- `git diff --check` موفق؛ Git پیام تبدیل LF به CRLF مطابق تنظیمات محیط می‌دهد.
- بررسی ارجاع‌های مستقیم `src` و `href` با پیشوند `~/` در Razor: صفر فایل گمشده؛ CSS تولیدی `OrganizationIntranet.styles.css` از بررسی فایل سورس مستثنا شد. این بررسی شامل تمام URLهای داخل CSS، مسیرهای پویا یا سرویس‌های بیرونی نیست.
- اجرای محلی در `http://127.0.0.1:5087`: Login، ForgotPassword و Error پاسخ ۲۰۰؛ مسیر `/` هدایت ۳۰۲ به Login.
- درخواست ناشناس به Portal، Profile، Admin و فهرست‌های Users، Roles، Applications و Permissions: هدایت ۳۰۲ به Login با ReturnUrl.
- Bootstrap RTL و app-toast.js از HTTP پاسخ ۲۰۰ دادند.

## ماتریس پذیرش بصری باقی‌مانده

این موارد هنوز اجرا نشده‌اند و برای تأیید بصری نهایی لازم‌اند:

| سناریو | بررسی لازم |
|---|---|
| عرض‌های ۳۶۰، ۷۶۸ و ۱۴۴۰ پیکسل | عدم اسکرول افقی ناخواسته، پوشیده‌نشدن فرم‌ها، هدر، منو و جدول |
| ورود و بازیابی رمز | کپچا، نمایش رمز، ارسال ناموفق، بازگشت دکمه از حالت انتظار، Toast |
| پورتال با حساب معتبر | جست‌وجوی دارای نتیجه و بدون نتیجه، منوها، Escape و فوکوس، اعلان‌ها |
| مدیریت با حساب ADMIN | سایدبار در موبایل، تم روشن/تیره، جدول‌ها، اعتبارسنجی فرم، منوی حساب |
| پروفایل و خروج | نمایش و ویرایش معتبر/نامعتبر، خروج و رفتار دکمه بازگشت |
| دسترس‌پذیری | ترتیب Tab، فوکوس قابل مشاهده، نام کنترل‌ها، کنتراست و بزرگ‌نمایی ۲۰۰٪ |

در این اجرا ورود با حساب واقعی، ارسال فرم تغییردهنده داده، آزمون بصری مرورگر و تصویربرداری انجام نشده است؛ پاسخ HTTP و بیلد به‌تنهایی صحت این سناریوها را اثبات نمی‌کنند.
